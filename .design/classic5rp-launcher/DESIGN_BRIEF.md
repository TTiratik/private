# Design Brief: Classic 5 RP — Game Launcher

## Problem

Игрок хочет зайти на свой любимый сервер Classic 5 RP как можно быстрее и без лишних
действий. Сейчас (аналог — лаунчер GTA5 RP) ему нужно видеть в одном окне: какие серверы
есть, сколько там людей онлайн, что нового на проекте, и одной кнопкой запуститься в игру.
Лаунчер — это «входная дверь» проекта: он должен выглядеть дорого и внушать доверие, иначе
игрок сомневается, что проект серьёзный.

Отдельная боль владельца проекта: клиентский лаунчер не должны за полчаса декомпилировать,
переклеить логотип и выдать за свой. Технически Electron нельзя сделать неломаемым, но
ценную логику можно убрать на сервер, а клиент — максимально затруднить для разбора.

## Solution

Десктопное окно без системной рамки, фиксированного размера, со своим заголовком и
кнопками «свернуть / закрыть». Слева — брендовый блок (логотип Classic 5 RP, счётчик «игроков
онлайн») и список серверов с их онлайном, выбранный сервер подсвечен. Справа — карточка
выбранного сервера: крупное имя сервера, блок друзей (позже), карусель новостей и крупная
кнопка **«Играть»**. При запуске лаунчер сворачивается, и игрок видит полноэкранный экран
загрузки в стиле проекта (ночной город, подпись «Запуск игры», оранжевый индикатор прогресса).

Весь контент (серверы, онлайн, новости, сообщества) лаунчер получает по HTTP из бэкенд-API.
Пока API нет — тот же контракт отдаёт локальная заглушка (моковый JSON), поэтому при
появлении реального API меняется только базовый URL, а не интерфейс.

## Experience Principles

1. **Один клик до игры** — всё второстепенное уступает место кнопке «Играть». Выбор сервера
   и запуск не должны требовать больше одного-двух действий.
2. **Живой проект, а не статичная картинка** — онлайн, новости и статусы серверов
   обновляются сами; интерфейс показывает, что за проектом стоит живое сообщество.
3. **Ценность — на сервере, не в клиенте** — лаунчер только отображает данные и отправляет
   подписанные запросы. Никаких секретов, прямых игровых путей или бизнес-логики в клиенте,
   которые имело бы смысл воровать.

## Aesthetic Direction

- **Philosophy**: Тёмный «gaming AAA» интерфейс — глубокий сине-стальной фон, атмосферное
  фоновое изображение ночного города, холодные тёмные панели со стеклянным (glassmorphism)
  эффектом, тёплый оранжевый как единственный яркий акцент.
- **Tone**: Солидный, атмосферный, премиальный. Не «ярко и мультяшно», а «ночь, город,
  неон вдалеке».
- **Reference points**: Экран загрузки Classic 5 RP (ночной Лос-Сантос, оранжевый прогресс-
  бар), лаунчер GTA5 RP (структура: список серверов слева, карточка + новости справа),
  лаунчеры Rockstar / Epic Games (темнота, крупные карточки новостей).
- **Anti-references**: Светлые «офисные» дашборды; пёстрые детские геймерские темы с
  кислотными градиентами; перегруженные RGB-интерфейсы.

## Existing Patterns

Чистый старт — в репозитории нет UI-кода, токенов, компонентов или фреймворка. Устанавливаемые
соглашения становятся каноном для последующих скиллов (design-tokens, frontend-design).

- Typography: не задано. Рекомендация — один гротеск: **Inter** (или системный) для текста,
  плотное начертание для заголовков серверов и логотипа.
- Colors: см. палитру выше (новая).
- Spacing: не задано. Рекомендация — шкала на базе 4px (4/8/12/16/24/32).
- Components: нет. Всё новое.

## Key Interactions

- **Выбор сервера**: клик по строке в `ServerList` → строка подсвечивается оранжевым,
  `ServerCard` справа перерисовывается под выбранный сервер (имя, новости, статус). Выбор
  запоминается между запусками.
- **Запуск игры**: клик «Играть» → кнопка переходит в состояние `launching` (спиннер,
  блокировка повторного клика) → окно лаунчера сворачивается → показывается `LoadingOverlay`
  с прогрессом. Если сервер офлайн/тех.работы — кнопка `disabled` + подсказка.
- **Новости**: карусель листается стрелками и колесом; автопрокрутка каждые ~6 c,
  останавливается при наведении. Клик по карточке — модалка или внешняя ссылка.
- **Обновление данных**: авто-поллинг онлайна каждые N секунд + ручная кнопка refresh
  (иконка крутится во время запроса). При ошибке — тост, старые данные остаются на экране.
- **Окно**: верхняя полоса — зона перетаскивания; свернуть/закрыть — кастомные кнопки;
  при запуске игры — опционально свернуть в трей.

## API Interaction (контракт клиент ↔ сервер)

Клиент общается с бэкендом только по HTTPS-JSON. Базовый URL в конфиге
(`API_BASE_URL`). Пока API нет — тот же набор эндпоинтов отдаёт локальный мок с идентичной
схемой, подменяется одним флагом. Весь сетевой код изолирован в одном слое (`src/renderer/api/`),
UI не знает, мок это или прод.

Планируемые эндпоинты (v1):

| Метод | Путь | Назначение | Ответ (схема) |
|---|---|---|---|
| `GET` | `/api/v1/servers` | Список серверов + онлайн + статус | `[{ id, name, slug, online, status: "online"\|"offline"\|"maintenance", order, iconUrl }]` |
| `GET` | `/api/v1/servers/:id` | Детали сервера для карточки | `{ id, name, connectUrl, friendsOnline, description }` |
| `GET` | `/api/v1/news?server=:id` | Новости (общие + по серверу) | `[{ id, title, imageUrl, link, publishedAt }]` |
| `GET` | `/api/v1/communities` | Ссылки сообществ | `[{ label, url, icon }]` |
| `GET` | `/api/v1/launcher/version` | Проверка версии лаунчера | `{ latest, mandatory, downloadUrl }` |
| `POST` | `/api/v1/session/launch` | Регистрация запуска, выдача токена подключения | `{ ticket, connectUrl, expiresAt }` |

Правила:
- Все запросы шлют заголовок версии лаунчера и (позже) токен авторизации.
- `connectUrl` / `ticket` выдаёт **сервер** в момент запуска — клиент их не хранит и не
  вычисляет. Это и есть защита «ценность на сервере».
- Поллинг онлайна: `GET /servers` каждые ~30 c. Таймаут 8 c, 1 ретрай, затем тост.
- Клиент никогда не доверяет локальным данным для доступа к игре — решение о запуске
  подтверждает сервер (`/session/launch`).
- IPC: сеть и запуск процесса игры — только в main-процессе Electron через
  `contextBridge`; renderer не имеет `nodeIntegration`.

## Responsive Behavior

Это десктопное приложение фиксированного окна (ориентир **1100×650**, min ~1000×600),
поэтому полноценная мобильная адаптивность не нужна. Требование — корректно вести себя при:
- растягивании окна до максимума: левая колонка фиксированной ширины (~240px), правая
  тянется; карусель новостей показывает больше карточек;
- маленьком окне / низком разрешении: список серверов скроллится, карточки новостей
  ужимаются до 1–2 видимых со стрелками.
`LoadingOverlay` — всегда на весь экран окна поверх всего.

## Accessibility Requirements

- Контраст текста к фону ≥ 4.5:1 (приглушённый `#8A94A6` на тёмном — проверить, при
  необходимости поднять до `#9AA4B6`).
- Полная навигация с клавиатуры: Tab по вкладкам, серверам, кнопкам; Enter/Space —
  активация; стрелки — листание карусели и списка серверов.
- Видимый фокус-ринг (оранжевый outline) на всех интерактивных элементах.
- Кнопка «Играть» и статусы серверов имеют текстовые подписи/`aria-label`, а не только цвет
  (онлайн/офлайн не передаётся одним цветом — плюс иконка/текст).
- Экран загрузки анонсирует прогресс (`aria-live`), уважает `prefers-reduced-motion`
  (отключение автопрокрутки карусели и анимаций).

## Security / Anti-tamper Requirements (пункт 6)

Честно: Electron-клиент нельзя сделать недекомпилируемым. Цель — поднять порог и убрать
ценность из клиента. Требования к сборке:
- **Логика и секреты — на сервере.** В клиенте нет ключей, прямых игровых путей,
  приватных URL. Запуск санкционирует API (`/session/launch`).
- **V8-байткод**: сборка renderer/main компилируется в байткод (`bytenode`), в пакете нет
  читаемого JS с бизнес-логикой.
- **Обфускация** оставшегося JS (`javascript-obfuscator`) на этапе билда.
- **asar + integrity**: упаковка в `app.asar` с `asarIntegrity`; подмена архива ломает
  запуск. Сборку подписывать (code signing) при релизе.
- `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`, строгий CSP,
  отключённый DevTools в проде.
- Проверка версии (`/launcher/version`): устаревший/`mandatory` клиент не пускает в игру.
- Это замедляет и демотивирует копирование, но не гарантирует 100%. Явно зафиксировано как
  ограничение технологии.

## Out of Scope (v1)

- Реальный бэкенд-API (делается позже; сейчас — мок с тем же контрактом).
- Авторизация / аккаунты / система друзей (блок друзей — заглушка «позже»).
- Автообновление самого лаунчера и скачивание/патчинг файлов игры (только проверка версии).
- Встроенный чат, магазин, донат, внутриигровая статистика.
- Локализация кроме русского.
- macOS/Linux сборки (цель — Windows).
